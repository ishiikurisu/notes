# Standard Makefile

I manage many personal projects, each of them using different programming languages, build tools, targetting different operating systems and platforms. As such, it can get really bad really quick if I end up having to learn a different set of commands to handle each one of them. Because of this, I have developed a set of defaults that basically all of my personal projects share for managing common code operations. I call this the "standard makefile".

The main restraints are:

* The fundamental tools should be common across different operating systems
* Only learn a couple of commands and use them everywhere

The main tool here is `make` [1], a common utility in UNIX systems that allow developers to describe the files that should be generated by a build process and the commands to get there. This description is made through a `makefile`.

The main steps are the following:

* build
* test
* run
* pack
* install
* save
* load
* clean

"Build" is used to manage dependencies and build the main application. This should be the default step.

"Test" is used to run unit tests using whatever tools are available for the project. If this step gets too complicated, it might be more interesting to delegate its description to another script.

"Run" is used to execute the application in a quick manner, usually for testing purposes.

"Pack" is used to create a distributable version of the application.

"Install" is used to deploy the application (either by pushing it to the server or by copying the distributable version to an executable path).

"Save" is used to create images for the application, usually through Docker.

"Load" is save's counterpart, where a Docker image is loaded into the system.

"Clean" is used to purge temporary artifacts from the repository. Commonly translates to `git clean`

I have one unusual practice when writing these files since the main steps are almost always described as "phony", meaning that they should always be executed, ignoring what was already built before.

The final example will look like this:

```
.PHONY: default
default: build

.PHONY: build
build:
	lein uberjar

.PHONY: test
test:
	lein test

.PHONY: run
run:
	lein exec
	# might also be through Docker for production environments

.PHONY: pack
pack: build
	cp target/uberjar/app.jar .

.PHONY: install
install: pack
	cp app.jar ~/.local/bin

.PHONY: save
save: pack
	docker build -t image-name .
	docker save image-name > container.tar

.PHONY: load
load:
	docker load < container.tar

.PHONY: clean
clean:
	rm -rf target

```
